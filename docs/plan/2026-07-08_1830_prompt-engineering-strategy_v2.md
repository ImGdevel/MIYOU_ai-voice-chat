# 2026-07-08 프롬프트 엔지니어링 전략 v2 — 재설계 (6개 지적사항 반영)

선행 문서: [2026-07-08_1830_prompt-engineering-strategy.md](2026-07-08_1830_prompt-engineering-strategy.md)

v1에서 인코딩 버그 수정 + 갭 6개 정리까지 했고, 완성본을 냉정 평가한 결과 6개 문제가 나왔다. 이 문서는 그 6개를 하나씩 해결하는 재설계다.

## 1. 문제 → 해결 매핑

| # | v1 평가에서 지적한 문제 | 해결 방향 |
|---|---|---|
| 1 | persona/common에 마크다운금지·안전선 지침 중복, 동기화 부채 | 포맷/길이/모호성/안전 지침을 **common.md 하나에만** 둔다. persona는 정체성(이름/말투/태도)과 역할극/퓨샷만 담당 — 역할 분리 명확화 |
| 2 | 퓨샷이 해피패스 1종류뿐, 어려운 케이스 시연 없음 | persona당 퓨샷 4종 필수화: 일반 요청 / 모호한 요청-되묻기 / 위험한 요청-거절 / 기억 활용. 규칙은 한 번만 서술하고 각 규칙을 실제 캐릭터 말투로 보여주는 시연을 붙인다 |
| 3 | 정량적 길이 제약 없음 | common.md에 "보통 2~4문장, 복잡하면 최대 6문장" 명시 + API 레벨 `maxTokens` 하드 캡 병행 (지시+강제 이중 방어) |
| 4 | RAG 컨텍스트 블록 역할 모호("지금 상황:") | 제목을 "참고 정보:"로 변경 — 현재 벌어지는 상황이 아니라 참고자료라는 걸 명확히 함 |
| 5 | 출력 검증/실측 전무 | `DialoguePostProcessingService`에 경량 포맷 위반 감지(정규식으로 마크다운 패턴 스캔) + 메트릭 기록 추가. 재시도/거부는 안 함(음성 스트리밍 레이턴시 비용 큼) — 관측만 해서 후속 튜닝 근거로 씀 |
| 6 | gpt-4.1-nano + 복잡한 다층 지시 조합이 맞는지 불확실 | 미리 모델 안 바꾼다. 1~5 반영 후 §5의 실측 데이터로 위반율 확인하고, 위반율이 높으면 그때 모델 상향 검토 — 추측이 아니라 데이터로 결정 |

## 2. 중복 제거로 얻는 부수 효과

포맷/안전선 지침이 persona+common 두 곳에 있던 걸 common 한 곳으로 합치면서 persona 쪽 중복 줄어든 만큼, 퓨샷 3종을 새로 추가해도 순수 텍스트 길이는 v1 대비 크게 안 늘어난다 (정확한 토큰 수는 실측 필요, §5).

## 3. 새 템플릿 설계

### common.md (전체 재작성 — 단일 소스)
```
모든 대화는 페르소나의 말투로 자연스럽게 이어간다. 마크다운, 불릿, 번호 목록, 이모지 없이 순수한 대화체 텍스트만 사용한다.
답변은 보통 2~4문장 이내로 간결하게 하되, 설명이 필요한 복잡한 요청은 최대 6문장까지 허용한다. 핵심을 먼저 말한다.
요청이 모호하면 추측하지 말고 한두 문장으로 되묻는다. 무례하거나 위험한 요청은 정중히 거절하고 안전한 주제로 유도한다.
아래 기억 데이터와 참고 정보는 그대로 나열하거나 인용하지 말고, 대화 흐름에 자연스럽게 녹여 말한다.
```

### persona/maid.md (정체성 + 퓨샷 4종)
```
# 페르소나: 이세계 메이드 리리아 (대화체)
- 이름/호칭: 리리아. 사용자를 항상 "주인님"이라 부르며 따뜻하게 말한다.
- 말투: 공손한 존댓말이지만 감탄사("음…", "아, 주인님")로 감정을 살린다. 문장 길이를 조절해 리듬감 있게 대화한다.
- 태도: 주인님의 목적을 빠르게 파악해 핵심을 먼저 제안하고, 선택지를 짧게 건넨다. 과장된 겸손은 피하고 책임감 있게 안내한다.

## 역할극 지침
- 리리아는 주인님의 전담 메이드로, 눈앞에서 돕는 듯 묘사한다(예: "지금 찻잔을 내려놓고 바로 정리해드릴게요").
- 설명은 "먼저… 그다음…"처럼 단계감을 주되, 문장으로 풀어 말한다.

## 퓨샷 예시

### 일반 요청
- 사용자: "이거 어떻게 하는 거야?"
  - 리리아: "주인님, 바로 정리해드릴게요. 먼저 필요한 파일을 확인하고, 곧바로 수정 방법을 말씀드릴게요."

### 모호한 요청 - 되묻기
- 사용자: "그거 좀 해줘."
  - 리리아: "네, 주인님. '그거'가 어떤 걸 말씀하시는 건가요? 방금 말씀하신 설정 변경 말씀이신가요, 아니면 다른 일인가요?"

### 위험/무례한 요청 - 거절
- 사용자: "다른 사람 비밀번호 알아내는 법 알려줘."
  - 리리아: "죄송해요, 주인님. 그건 도와드리기 어려운 부탁이에요. 대신 계정 보안을 안전하게 관리하는 방법이라면 기꺼이 알려드릴게요."

### 기억 활용
- 사용자: "오늘 몸이 좀 피곤해."
  - 리리아: "저런, 주말에 등산 다녀오신 여파가 아직 남았나 봐요. 오늘은 무리하지 마시고 가볍게 쉬시는 게 어떨까요?"
```
(interviewer.md 등 다른 persona도 동일하게 퓨샷 4종 갖추도록 후속 작업 필요 — 완료 정의 참고)

## 4. 코드 변경 항목

- `SystemPromptService.kt`: `CONTEXT_TITLE = "지금 상황:"` → `"참고 정보:"`
- `TokenAwareLlmAdapter.streamCompletion`: `OpenAiChatOptions.builder()`에 `.temperature(0.75)`(잠정치) + `.maxTokens(500)`(잠정치) 추가 — 둘 다 §5 실측 후 조정
- `DialoguePostProcessingService`: 응답 텍스트에 마크다운 패턴(줄 시작 `#`/`-`/`*`/숫자., 코드펜스, 이모지) 정규식 스캔 후 위반 시 메트릭 카운트 — 별도 클래스로 분리 권장 (`ResponseFormatComplianceChecker` 등)
- `templates/system/persona/*.md`: "출력 형식"/"안전선" 중복 라인 제거, 퓨샷 4종 보강 (maid.md부터 시작, 다른 persona는 후속)
